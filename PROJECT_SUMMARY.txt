PROJECT OVERVIEW
================================================================================
The WhatsApp Appointment Booking System (WABA) is a production-ready chatbot 
solution that enables patients to book, cancel, and reschedule doctor 
appointments through WhatsApp Business API. The system features interactive 
menus, automated reminders, and a comprehensive admin dashboard for healthcare 
providers.

TECHNOLOGY STACK
================================================================================
Backend:
- Node.js with TypeScript
- Express.js framework
- MySQL 8.0 database
- WhatsApp Business API integration
- node-cron for automated scheduling

Frontend:
- React 19.2.0 with Vite
- Material-UI components
- React Router for navigation
- Axios for API communication

External Services:
- Meta WhatsApp Business API
- ngrok for webhook tunneling
- MySQL database for data persistence

CORE SYSTEM FLOWS
================================================================================

FLOW 1: PATIENT APPOINTMENT BOOKING
────────────────────────────────────────────────────────────────────────────────
Entry Point: Patient sends "hi", "hello", or "book" to WhatsApp number

Step 1: Service Menu Display
- System presents interactive list with options:
  • 📅 Book Appointment
  • ❌ Cancel Appointment  
  • 🔄 Reschedule Appointment

Step 2: Category Selection
- Patient selects "Book Appointment"
- System displays medical categories (Cardiology, Orthopedics, etc.)
- Patient selects preferred category

Step 3: Doctor Selection
- System shows available doctors in selected category
- Patient chooses specific doctor

Step 4: Date Selection
- System presents next 7 days as options
- Displays as "Today", "Tomorrow", or formatted dates
- Patient selects preferred date

Step 5: Time Slot Selection
- System shows available time slots with capacity indicators
- Format: "10AM - 11AM [2/5]" (2 booked out of 5 total)
- Only displays slots with available capacity
- Filters out past time slots for current day

Step 6: Patient Information
- System requests patient's full name
- Patient enters name via text message

Step 7: Confirmation
- System displays appointment summary with interactive buttons
- Patient confirms or cancels the booking
- Upon confirmation, appointment is saved with "confirmed" status

Technical Implementation:
- Session state management tracks conversation progress
- Database queries check real-time slot availability
- Capacity management prevents overbooking
- Interactive WhatsApp elements enhance user experience

FLOW 2: APPOINTMENT CANCELLATION
────────────────────────────────────────────────────────────────────────────────
Entry Point: Patient selects "Cancel Appointment" or types "cancel"

Step 1: Appointment Retrieval
- System queries database for patient's active appointments
- Filters appointments that are >2 hours away (cancellation policy)
- Shows only "confirmed" and "accepted" status appointments

Step 2: Appointment Selection
- Displays patient's cancellable appointments in interactive list
- Format: "DD/MM HH:MM - Patient Name"
- Patient selects appointment to cancel

Step 3: Cancellation Confirmation
- Shows detailed appointment information
- Presents confirmation buttons: "Yes, Cancel" / "No, Keep It"
- Patient confirms cancellation decision

Step 4: Processing
- Updates appointment status to "cancelled" in database
- Frees up slot capacity for other patients
- Sends confirmation message to patient

Technical Implementation:
- Time-based filtering prevents last-minute cancellations
- Database transactions ensure data consistency
- Slot capacity automatically recalculated

FLOW 3: APPOINTMENT RESCHEDULING
────────────────────────────────────────────────────────────────────────────────
Entry Point: Patient selects "Reschedule Appointment" or types "reschedule"

Step 1: Current Appointment Selection
- System shows patient's reschedulable appointments
- Applies same 2-hour policy as cancellation
- Patient selects appointment to reschedule

Step 2: Reschedule Confirmation
- Displays current appointment details
- Patient confirms intent to reschedule

Step 3: New Booking Process
- Follows same flow as new booking (category → doctor → date → time)
- Patient name is auto-filled from existing appointment
- Shows only available slots (excludes fully booked slots)

Step 4: Final Confirmation
- Shows side-by-side comparison:
  • OLD: Previous appointment details
  • NEW: New appointment details
- Patient confirms the reschedule

Step 5: Processing
- Updates existing appointment record (same ID)
- Old slot capacity freed, new slot capacity reduced
- Sends confirmation with new appointment details

Technical Implementation:
- Preserves appointment ID for continuity
- Excludes current appointment from capacity calculations
- Atomic database updates prevent conflicts

FLOW 4: AUTOMATED REMINDER SYSTEM
────────────────────────────────────────────────────────────────────────────────
Trigger: Daily cron job at 6:00 PM

Step 1: Appointment Identification
- Cron job queries database for next day's appointments
- Filters appointments with status: confirmed, accepted, visited
- Excludes cancelled appointments

Step 2: Reminder Message Generation
- Creates personalized reminder message for each patient
- Includes: patient name, doctor, date, time, arrival instructions
- Adds cancellation option via reply

Step 3: Message Delivery
- Sends WhatsApp message to each patient
- Includes interactive elements for confirmation/cancellation
- Logs delivery status

Step 4: Response Handling
- Processes patient responses to reminders
- Handles confirmation acknowledgments
- Processes cancellation requests with appointment ID

Technical Implementation:
- node-cron scheduler: '0 18 * * *' (6 PM daily)
- Batch processing for multiple appointments
- Error handling for failed message deliveries

FLOW 5: ADMIN DASHBOARD MANAGEMENT
────────────────────────────────────────────────────────────────────────────────
Access: Web interface at /admin route

Dashboard Tab:
- Displays all appointments in tabular format
- Date filtering with From/To date pickers
- Quick navigation: Previous Week, This Week, Next Week
- Status-based color coding for appointments
- Action buttons for appointment management

Today's Visits Tab:
- Shows current day's appointments
- Status progression: Pending → Accepted → Visited → Completed
- Real-time status updates
- Patient check-in management

Doctor Calendar Tab:
- Weekly calendar view per doctor
- Visual seat representation with patient names
- Color-coded status indicators
- Empty slot management

Follow-ups Tab:
- Create and manage follow-up messages
- Template-based or custom message options
- Send/Resend functionality with status tracking
- Patient communication history

Doctor Management:
- Add new doctors with category assignment
- Edit existing doctor information
- Delete doctors with confirmation prompts
- Category-based organization

Time Slot Configuration:
- Add time slots with custom capacity
- AM/PM time picker interface
- Capacity management per slot
- Availability toggle controls

Technical Implementation:
- React-based responsive interface
- Real-time data fetching with Axios
- Material-UI components for consistency
- State management for form handling

FLOW 6: WEBHOOK MESSAGE PROCESSING
────────────────────────────────────────────────────────────────────────────────
Trigger: Incoming WhatsApp message to business number

Step 1: Webhook Reception
- Express server receives POST request from Meta
- Immediate 200 OK response to acknowledge receipt
- Message extraction from webhook payload

Step 2: Message Validation
- Validates message structure and content
- Extracts sender phone number and message text
- Handles different message types (text, interactive responses)

Step 3: Session Management
- Retrieves or creates conversation session for phone number
- Tracks conversation state and booking data
- Manages session lifecycle and cleanup

Step 4: Business Logic Processing
- Routes message to appropriate handler based on session state
- Processes booking, cancellation, or reschedule requests
- Handles restart commands and error scenarios

Step 5: Response Generation
- Generates appropriate WhatsApp response
- Sends interactive elements (lists, buttons) or text messages
- Updates session state for next interaction

Technical Implementation:
- Express.js webhook endpoint
- In-memory session storage (production should use Redis)
- State machine pattern for conversation flow
- Error handling and logging throughout

DATABASE SCHEMA
================================================================================

categories
├── id (INT, PRIMARY KEY, AUTO_INCREMENT)
└── name (VARCHAR(100), NOT NULL)

doctors
├── id (INT, PRIMARY KEY, AUTO_INCREMENT)
├── name (VARCHAR(100), NOT NULL)
└── category_id (INT, FOREIGN KEY → categories.id)

time_slots
├── id (INT, PRIMARY KEY, AUTO_INCREMENT)
├── doctor_id (INT, FOREIGN KEY → doctors.id)
├── date (DATE)
├── start_time (TIME, NOT NULL)
├── end_time (TIME, NOT NULL)
├── capacity (INT, DEFAULT 5)
└── is_available (BOOLEAN, DEFAULT TRUE)

appointments
├── id (INT, PRIMARY KEY, AUTO_INCREMENT)
├── phone (VARCHAR(20), NOT NULL)
├── patient_name (VARCHAR(100), NOT NULL)
├── category (VARCHAR(100), NOT NULL)
├── doctor (VARCHAR(100), NOT NULL)
├── date (DATE, NOT NULL)
├── time_slot (VARCHAR(50), NOT NULL)
├── status (ENUM: pending, confirmed, accepted, visited, completed, cancelled)
├── token_number (INT)
└── created_at (TIMESTAMP, DEFAULT CURRENT_TIMESTAMP)

followups
├── id (INT, PRIMARY KEY, AUTO_INCREMENT)
├── phone (VARCHAR(20), NOT NULL)
├── patient_name (VARCHAR(100))
├── message_type (ENUM: custom, template)
├── template_name (VARCHAR(100))
├── custom_message (TEXT)
├── status (ENUM: pending, sent)
├── sent_at (TIMESTAMP)
└── created_at (TIMESTAMP, DEFAULT CURRENT_TIMESTAMP)
